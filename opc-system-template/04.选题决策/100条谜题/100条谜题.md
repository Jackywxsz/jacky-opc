# 100 条谜题生成模板

> 公开版只提供生成方法和空白模板，不提供原系统里的完整选题资产。

谜题的作用不是替你写标题，而是把用户心里的“为什么”“怎么做到”“如果这样会怎样”提前找出来。每条谜题都应该服务于一个明确用户、一个真实痛点和一个可验证的内容方向。

## 四类谜题

| 类型 | 用户反应 | 适合内容 |
| --- | --- | --- |
| HOW | 怎么做到？ | 教程、流程、工具、方法论 |
| WHY | 为什么会这样？ | 观点、趋势、反常识、案例拆解 |
| WHAT IF | 如果这样做会怎样？ | 实验、挑战、预测、过程记录 |
| WOW | 这也可以？ | 极致案例、极端数据、强反差故事 |

## 生成步骤

1. 写清楚目标用户：这条内容给谁看？
2. 写清楚用户卡点：他现在困在哪里？
3. 写出常见认知：大多数人以为原因是什么？
4. 写出认知缺口：真正值得追问的地方在哪里？
5. 改成一句“为什么 / 怎么 / 如果 / 竟然”的问题。

## 句式模板

```text
为什么 [目标用户] 越 [常见动作]，反而越 [反直觉结果]？
为什么大家都在讲 [热门做法]，真正卡住人的却是 [隐藏卡点]？
怎么用 [低门槛动作]，解决 [高频痛点]？
如果 [目标用户] 把 [旧流程] 改成 [新流程]，会发生什么？
为什么 [看起来正确的做法]，可能正在放大 [实际问题]？
```

## 少量示范

这些只是句式示范，不是可直接复制的私有选题。

1. 为什么 [目标用户] 越 [常见动作]，反而越 [负面结果]？
2. 为什么 [目标用户] 最该优化的不是 [表层动作]，而是 [底层能力]？
3. 怎么把一次 [具体任务] 沉淀成下次可以复用的 [资产类型]？
4. 如果 [目标用户] 不再从 [旧起点] 开始，会发生什么？
5. 为什么 [目标用户] 看起来缺 [表层资源]，本质上可能是缺 [底层机制]？
