# 选题系统

Jacky-OPC 把选题看成核心引擎。写作可以加速，结构可以套用，但选题决定这条内容有没有被看见和被记住的机会。

## 选题决策三问

拿到任何选题，先问：

1. 目标用户真的关心吗？
2. 我有没有独特视角？
3. 现在讲有没有时效或情绪窗口？

三个都是，优先做。两个是，值得排期。只有一个是，先放进选题池观察。

## 两个选题库

### 100 个谜题

谜题负责制造好奇心。一个选题最好能让用户产生“为什么”“怎么做到”“如果这样会怎样”的反应。

开源模板不提供现成的完整谜题库，只提供生成方法和少量句式示范。真正有价值的谜题，必须来自你自己的目标用户、长期问题和真实反馈。

四类谜题：

- `HOW`：怎么做
- `WHY`：为什么
- `WHAT IF`：如果这样会怎样
- `WOW`：极致事实让大脑预测失灵

### 100 个非共识

非共识负责制造判断力。它不是为了反着说，而是把你长期观察到但大多数人还没意识到的规律说出来。

开源模板不提供现成的完整观点库。你需要在创作、发布和复盘中，逐步把自己的判断沉淀出来。

好的非共识通常长这样：

- 大多数人以为 A，其实真正重要的是 B。
- 表面上是工具问题，本质上是系统问题。
- 普通人不缺方法，缺的是能持续回流反馈的结构。

## 选题卡片

每个正式选题建议写成一张卡片：

```markdown
# 选题标题

## 目标用户

这条内容写给谁？

## 用户痛点

他现在卡在哪里？

## 谜题类型

HOW / WHY / WHAT IF / WOW

## 非共识判断

大多数人怎么想？我不同意什么？

## 核心判断

一句话说清这条内容想让用户带走什么。

## 证据素材

真实案例、数据、个人经历、对标内容。

## 推荐结构

观点输出 / 教程演示 / 案例拆解 / 故事驱动 / 认知升级
```

## 筛选标准

一个选题进入写作前，至少要满足：

- 能一句话讲清核心判断。
- 有一个让人停下来的信息点。
- 和近期内容不重复。
- 能找到足够证据支撑。
- 能沉淀回一个方法论或经验。
